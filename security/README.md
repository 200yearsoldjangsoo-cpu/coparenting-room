## 2. 서버 함수(bb-session)에서 해야 할 것 — 코드가 이 저장소에 없어 직접 못 고침

Supabase 대시보드 > Edge Functions > bb-session 에서 아래를 확인·반영할 것.

```ts
// (1) 세션 만들 때: 녹화·로그 끄기, 컨텍스트(로그인 상태) 저장 안 함
const session = await bb.sessions.create({
  projectId: Deno.env.get("BROWSERBASE_PROJECT_ID")!,
  keepAlive: false,
  timeout: 180,                       // 승인 대기 2분 + 여유
  browserSettings: { recordSession: false, logSession: false },
  // context 옵션은 넣지 않음 (넣으면 건보·홈택스 로그인 쿠키가 남음)
});

try {
  // ... 간편인증·조회 ...
  // (2) 화면 글자를 앱으로 보내기 전에 주민등록번호 뒷자리 가리기
  const safe = text.replace(/\b(\d{6})\s*[-–]?\s*[1-8][\d*Xx●•]{6}\b/g, "$1-*******");
  send({ step: "data", text: safe });
} finally {
  // (3) 성공·실패와 상관없이 세션 즉시 종료
  await bb.sessions.update(session.id, {
    projectId: Deno.env.get("BROWSERBASE_PROJECT_ID")!,
    status: "REQUEST_RELEASE",
  });
}
```

체크리스트

- [ ] `console.log`로 요청 본문(이름·생년월일·휴대폰)이나 화면 글자를 찍는 곳이 없을 것 (Supabase 함수 로그에 남음)
- [ ] 이름·생년월일·휴대폰을 DB 테이블에 넣는 곳이 없을 것
- [ ] 초대코드는 서버에서 검사하고 코드별 하루 호출 횟수 제한 (남이 내 함수로 Browserbase 요금을 쓰는 것 방지)
- [ ] CORS `Access-Control-Allow-Origin`을 `https://coparenting-room.vercel.app`로만
- [ ] Browserbase 대시보드에서 기존 세션 녹화가 남아 있으면 삭제 (기본 설정은 녹화 켜짐, 최대 30일 보관)
- [ ] BROWSERBASE_API_KEY는 Supabase Secrets에만, 이 저장소(공개)에는 절대 넣지 않기

## 3. 데이터베이스 접근 통제

`security/rls_check.sql` 1단계를 실행해 지금 정책을 확인한다. 2026-11-21 공개 키로 점검한 결과는 다음과 같다.

| 테이블 | 익명 읽기 | 판단 |
|---|---|---|
| homes | 가능 | 미니홈피 공개 목적이라 정상. 다만 쓰기가 자기 것만 되는지 확인 필요 |
| notes | 가능 | 응원 공개 목적이라 정상. from_id 위조 차단 여부 확인 필요 |
| requests | 빈 배열 | 읽기 차단된 것으로 보임(연락처 보호) |

쓰기 권한은 실제 데이터를 건드리게 되어 점검하지 않았다.
